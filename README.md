# good_boilerplate_cli

Mason workspace for generating Flutter starter projects.

## Setup

```sh
dart pub global activate mason_cli
mason get
```

## Generate a Starter

From this Mason workspace:

```sh
cd /Users/zianfahrudy/Documents/good_boilerplate_cli
mason get
mason make flutter_starter -q
```

Example with custom app metadata:

```sh
mason make flutter_starter -q \
  --project_name my_app \
  --app_id id.ziandev.my_app \
  --app_name "My App" \
  --description "A production-ready Flutter starter."
```

To use the brick from any directory, register it globally once:

```sh
mason add -g flutter_starter --path /Users/zianfahrudy/Documents/good_boilerplate_cli/bricks/flutter_starter
```

Then run from the target output folder:

```sh
cd /Users/zianfahrudy/Documents
mason make flutter_starter
```

Use `-q` when generating if you want Mason to hide the long per-file `created ...` list and keep the output concise.

The `flutter_starter` brick provides a ready baseline that can be expanded with native platform flavor settings when bundle ids, schemes, and app icons are finalized.
By default, its post-generation hook runs `flutter create` to add `android`, `ios`, `web`, and `macos` platform folders.
Do not use `--no-hooks` if you want those native platform folders.

## Current Starter Features

- Dev and prod flavor entry points.
- Native Flutter platform folders generated by `flutter create`: `android`, `ios`, `web`, and `macos`.
- VS Code launch configurations for dev and prod.
- Per-flavor config for app id, app name, base API URL, network logging, and upgrade checks.
- Dio, Talker Dio logger, Flutter Bloc/Cubit, GoRouter, cached network images, GetIt, Upgrader.
- Json Serializable setup with an example model.
- Three-slide reusable onboarding flow with stepper, headline, subheadline, illustration, button, and trusted info.
- Settings page with reusable rows/cards and persisted dark/light mode.
- Reusable paywall page with RevenueCat plans, dummy fallback plans, delayed close button, free-trial toggle, restore, terms, and privacy links.
- Reusable daily quota service using local storage for per-feature usage limits.
- Reusable RevenueCat service with default offering identifier `default`.
- Reusable AdMob service and banner/interstitial/rewarded helpers.
- Reusable theme colors and typography.
